# 📔 Bullet Journal

종이 노트처럼 빠르게 기록하는 개인용 불렛저널입니다. Google 계정으로 로그인하면 여러 기기에서 같은 기록을 사용할 수 있습니다.

## 매일 사용하기

1. **오늘**에서 할 일·이벤트·메모를 입력하고 Enter 또는 **추가**를 누릅니다.
2. 중요한 할 일에 별표를 붙이면 **먼저 집중할 일**에 최대 3개가 표시됩니다.
3. 불릿은 완료·미완료 전환입니다. 오른쪽 **작업** 메뉴에서 날짜 이동·취소선·삭제를 선택합니다.
4. **이전 날짜의 미완료**에서 남은 일을 선택한 날짜로 옮깁니다. 자동 반복 이월은 하지 않습니다.
5. 같은 화면에서 습관과 **하루 한 줄**을 기록합니다. 긴 글과 사진은 **일기 펼치기**에서 작성합니다.
6. 달력과 시간표는 필요할 때 펼칩니다. 날짜 선택기와 앞뒤 버튼으로 과거 기록을 봅니다.

데스크톱에서는 최대 1360px까지 넓어집니다. Journal은 왼쪽 달력과 오른쪽 일기 공간으로 나뉘며, 작은 화면에서는 세로로 배치됩니다. Journal 달력의 점은 일기·사진·하루 한 줄이 있는 날짜입니다. 월 선택기로 오래된 날짜를 바로 찾고, **이전 기록 / 다음 기록**으로 빈 날짜를 건너뛸 수 있습니다. 달력의 월만 탐색할 때는 현재 작성 중인 일기 날짜가 바뀌지 않습니다.

이동한 항목에는 출발·도착 날짜가 표시됩니다. 복사본은 독립적인 기록이므로 원래 항목을 삭제해도 함께 삭제되지 않습니다. 삭제·완료·이동·복원·초기화 직후 **되돌리기**를 사용할 수 있습니다. 이후 같은 기록을 수정했다면 자동 되돌리기를 중단해 추가 변경을 보호합니다.

## 계획과 실제 시간표 · Weekly

오늘의 시간별 기록은 왼쪽 **계획**, 오른쪽 **실제**입니다. 기존 시간별 기록은 실제 쪽에 그대로 표시됩니다. 실제 기록을 새로 만들면 5가지 색 중 하나가 자동으로 선택되고, 편집창에서 언제든 다른 색으로 바꿀 수 있습니다. 계획 기록은 파란색으로 시작합니다. 빈 곳을 누르거나 드래그해 시간을 고른 뒤 내용을 저장하세요. 블록을 누르면 내용·시작/종료·계획/실제·색상을 편집할 수 있고, 손잡이로 이동하거나 위아래 가장자리로 길이를 조절할 수 있습니다. 키보드나 모바일에서는 각 열의 **＋** 버튼과 편집창을 사용할 수 있습니다.

**Weekly**는 월요일부터 일요일까지 날짜별 계획/실제를 나란히 표시합니다. 이전/다음 주·이번 주·날짜 선택으로 탐색하고 요일 날짜를 누르면 오늘 탭의 해당 날짜를 엽니다. 작은 화면에서는 주간 시간표를 가로 스크롤하세요.

두 탭은 동일한 `sched[날짜]`를 사용합니다. 한쪽에서 저장·이동·수정·삭제하면 반대쪽에도 반영되며 되돌리기도 함께 적용됩니다. 별도의 주간 데이터 복사본은 만들지 않습니다. 저장된 각 블록의 선택적 `kind`는 `plan` 또는 `actual`이고, 없는 과거 블록은 실제로 취급합니다. 백업과 PDF에도 계획/실제 구분이 포함됩니다.

## 저장과 여러 기기 사용

- 웹앱은 Firebase Authentication과 Firestore를 사용합니다. Markdown 파일과 웹앱 데이터는 서로 자동 동기화되지 않습니다.
- 입력 즉시 계정별 임시 초안을 브라우저에 보관하고, 마지막 입력 600ms 후 클라우드 저장을 시도합니다. 사진 원본은 임시 초안에 포함되지 않습니다.
- **저장 대기 / 저장 중 / 저장 완료 / 저장 실패 / 기록 충돌**과 임시 보관 실패를 구분해 표시합니다.
- 최초 클라우드 읽기가 실패하면 편집 화면을 열지 않습니다. **기록 다시 불러오기**로 재시도합니다. 연결 복구 후 계정별 초안을 복원하고 클라우드 변경과 비교합니다.
- 다른 날짜나 서로 다른 메모·습관 체크는 병합합니다. 같은 날짜의 할 일 목록·시간표·사진 목록은 각각 한 단위로 비교합니다. 양쪽에서 다르게 수정했다면 **충돌 확인**에서 내용을 보고 선택합니다. 겹치지 않는 변경은 선택과 관계없이 유지합니다.
- 저장 실패 시 초안을 유지하고 재시도합니다. 미저장 변경이 있을 때 창을 닫거나 로그아웃하면 알립니다.

배포 후 **모든 기기에서 새로고침**하세요. 예전 탭은 기존 전체 덮어쓰기 방식으로 저장할 수 있습니다. 공용 컴퓨터에서는 저장 완료 후 로그아웃하세요. 미전송 초안은 해당 브라우저에 남을 수 있습니다.

기기 공용 `bujo_v2` 초안을 새 Google 계정에 자동으로 가져오지 않습니다. 계정 구분이 없는 예전 로컬 기록은 기존 앱에서 별도로 확인하세요.

## 백업과 복원

- **백업 다운로드**: 기록과 현재 일기에 연결된 사진을 JSON으로 내려받습니다. 필요한 사진을 읽지 못하면 불완전한 백업 대신 오류를 알립니다.
- **백업 복원**: 앱이 만든 JSON을 검증하고 확인 후 현재 기록을 교체합니다. 사진은 현재 계정에 새 ID로 업로드합니다. 복원 전 현재 기록을 백업하세요.
- **PDF 내보내기**: Monthly에서 선택한 달의 할 일·시간표·일기·하루 한 줄·사진·습관을 인쇄하거나 PDF로 저장합니다.
- 사진을 일기에서 삭제하거나 초기화해도 되돌리기를 위해 사진 문서는 Firestore에 남습니다. 서버의 사진 영구 삭제가 아닙니다. 중단된 업로드·복원 역시 연결되지 않은 사진 문서를 남길 수 있습니다.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 화면, Google 로그인, Firestore 연결, 사진과 백업 |
| `journal-core.mjs` | 데이터 검증, 날짜 이동, 변경 병합 |
| `journal-sync.mjs` | 저장 상태, 초안 복구, 재시도, 충돌 처리 |
| `schedule.mjs` | 오늘·Weekly 공통 시간표, 계획/실제 구분 |
| `tests/journal.test.mjs` | 병합·저장·복구·이동 회귀 테스트 |
| `daily-log.md`, `weekly-log.md`, `monthly-log.md` | GitHub에서 직접 편집하는 별도 Markdown 템플릿 |
| `habit-tracker.md`, `goals.md` | 별도 습관·목표 템플릿 |

## 실행과 검증

정적 HTTP 서버 또는 기존 GitHub Pages에서 사용합니다. 파일을 더블 클릭하는 `file://` 방식은 모듈을 불러오지 못할 수 있습니다. `index.html`과 모든 `.mjs` 파일을 함께 배포하세요. Firebase의 승인된 도메인에 실행 주소가 등록되어 있어야 Google 로그인이 동작합니다.

추가 패키지 설치 없이 Node.js로 테스트합니다.

```sh
node --test tests/journal.test.mjs
```

자식 프로세스를 만들 수 없는 환경에서는 Node.js 22 이상에서 다음을 사용합니다.

```sh
node --test --test-isolation=none tests/journal.test.mjs
```

기존 `journals/{uid}`와 `journalPhotos/{id}`를 사용하므로 데이터 이전이나 컬렉션 추가는 필요하지 않습니다. 날짜·필드 단위로 변경을 비교하지만 저장 문서는 여전히 하나입니다. 기록이 커질 때 날짜별 문서 분리가 후속 작업입니다. 기존 Firebase 보안 규칙은 소유자만 각 문서를 읽고 쓰도록 설정되어 있어야 합니다. 운영 보안 규칙은 이 저장소에 포함되어 있지 않습니다.

배포 전 실제 계정에서 Google 로그인, 두 기기 간 변경, 재연결, 사진 포함 백업·복원, 모바일 조작과 PDF 출력을 확인하세요. 자동 테스트는 실제 Firebase나 로그인된 브라우저를 사용하지 않습니다.
